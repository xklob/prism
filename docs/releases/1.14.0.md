# prism 1.14.0

- Optional **Spotify compatibility** under **App settings → Audio → System audio**. Install and start Shizuku, enable the switch, then connect and approve both permissions. Android 13 or newer is required; root is optional. Spotify stays unmodified. Other apps retain ordinary system capture.
- Session recording requests the full visualizer canvas and follows rendered frames up to 60 fps, bounded by the display and encoder. Unsupported configurations fall back to lower targets. The recording control displays the configured size and rate. Actual frame rate depends on device performance.
- Four patterns remain: Kaleido, Wormhole, Mandelbrot, and Kaleidoscope. Aurora, Julia, and Equalizer are removed. Existing selections and saved looks using those modes migrate to Kaleido; retained pattern IDs stay compatible with the controller.
- Windows controller 0.4.0 offers the same four patterns.

The Shizuku helper routes only the installed Spotify UID's media playback and replays stereo PCM through the selected output. It releases the route on disconnect, projection cancellation/revocation, helper loss, or client death. It exposes no command-execution interface. Shizuku must be restarted after reboot. The existing Android device-capture prompt remains necessary.

Validation includes 95 JVM unit tests, Android release build/lint, mode and saved-look migration, native phone/tablet layout and help checks, GPU transitions, silent-video recording, and signed-release smoke checks. The real Shizuku UserService was exercised on Android 16 with a separately labelled synthetic source at 44.1/48 kHz and multiple capture policies, source restarts, volume comparison, stereo recording, canceled consent, and helper death. A video retained the 1280 × 800 emulator canvas; frame rate varied with rendering. The packaged Windows controller passed its tests and authenticated native-Windows startup, QR, command, and shutdown checks.

These are emulator and synthetic-source results. Actual Spotify's native renderer, Pixel Tablet output and performance, Bluetooth routing, and physical crowd synchronization still need field confirmation. Hidden Android routing APIs may vary by device and version; compatibility is optional and defaults to off.

Android versionCode: 18. The APK retains the existing release signing identity.
