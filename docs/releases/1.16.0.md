# prism 1.16.0

prism now runs as a standalone, self-hostable web app. Download **prism-web-1.16.0.zip**, extract it, and run `node serve.mjs --open`. For Windows with no Node installation, extract the controller ZIP and double-click **Start-prism-web.cmd**. For deployment on your own HTTPS server, copy the web ZIP’s extracted files. See the [web guide](https://github.com/xklob/prism/blob/v1.16.0/web/README.md).

- **Visuals** include all four Android shaders, per-pattern geometry and color controls, live motion, crossfades, bloom, blur, adaptive quality, fullscreen, and named looks with phrase cues. The responsive interface has System, Light, and Dark themes.
- **Audio** supports microphone input, browser-supported tab or system sharing, and local-file analysis with transport, seekable waveform, and timing markers. Both shipped BeatNet models and the shared Kotlin trackers run on-device. Manual timing, song assistance, and diagnostic CSV export are available.
- **Recording** saves the canvas with the connected soundtrack, or silent video. The browser negotiates its recording format. Controls and shared-screen pixels stay outside the recording.
- **Crowd controller 0.5.0** serves the complete app from its own local network address. Scan the web invitation to join the same show as Android participants. Audience devices verify signed schedules on LAN HTTP. Live microphone or tab capture requires HTTPS or localhost. The controller supports trusted HTTPS and a configurable self-hosted URL. [Controller guide](https://github.com/xklob/prism/blob/v1.16.0/controller/README.md)
- **Android** shares its timing implementation with the browser. The APK is versionCode 20 and retains the 1.15.0 signing identity.

## Verification

- Chromium covered the responsive controls, theme and look persistence, waveform seeking, offline analysis after reload, synthetic microphone input, tab-capture lifecycle with a synthetic picker, soundtrack recording, and CSV export. The two models reported 128 BPM on the original 128 BPM fixture and no grid on silence. The recorded file contained a non-silent audio track and the visualizer’s frames. Firefox also played the fixture and reported 128 BPM.
- Node tests covered the renderer assets, downbeat continuity, adaptive resolution, crowd client, and song lookup. Controller tests on Linux and native Windows covered signed web and UDP interoperability, role separation, local asset serving, and clock expiry. Chromium joined a private LAN HTTP show with the bundled signature verifier.
- All 100 Android unit tests passed. The signed release build and release lint completed. Android-only media-session controls and the optional Shizuku Spotify route remain available in the APK. The browser supports the capture surfaces offered by its OS. Physical handset synchronization, actual third-party player capture, and live AudD identification were outside these checks.
